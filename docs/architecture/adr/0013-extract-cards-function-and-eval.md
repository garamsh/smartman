# ADR 0013: Extract cards in a dependency-free Deno Edge Function limited per user in SQL, and choose its model with an eval in `tools/eval/`

> Status: accepted; its eval of vocabulary pages alone and its recommendation on F1 alone superseded by ADR-0051; its retry, its `CARD_RETRY_MODEL` and its model as a secret superseded by ADR-0071; its prompt as a versioned file superseded by ADR-0073
> Date: 2026-10-15

Append-only: once merged, the body below is not rewritten. A fact later found wrong is corrected in an appended note, not edited out; a revised decision is a new ADR that supersedes this one.

## Context

- Issue #25 (M6a) adds the server side of photo import; #30 builds the app flow on it. The PM decided there:
  - a Supabase Edge Function `extract-cards` in Deno, verify JWT on and anonymous callers refused, taking one base64 JPEG, PNG or WebP image of at most 6 MB and optional language hints;
  - a response of at most 100 cards, each side plain trimmed text of at most 500 characters, validated against a JSON schema;
  - an OpenRouter call with a structured-output schema, the model from `CARD_MODEL`, the prompt a versioned file;
  - the image never stored or logged; logs of user id, model, latency, token counts and outcome only;
  - the HTTP codes 401, 413, 415, 422, 429, 502 after one retry, and 503;
  - 30 extractions per user per day, counted in `extraction_usage`, which users read and only the function writes;
  - an eval over at least 20 deterministically generated samples, with the worker choosing between `supabase/functions/extract-cards/eval/` and `tools/eval/`, a $10 spend cap enforced by a dry estimate, and the recommendation rule.
- One candidate is Haiku with a Sonnet retry on invalid output. Without a second variable, that configuration could win the eval and still not be deployable.
- A count read and an insert made separately let two concurrent requests both pass at 29.
- The function needs three HTTP calls, all JSON over `fetch`. supabase-js would add a pinned npm dependency and a lock file to cover them.
- The engine's reference values are already generated by a uv script with pinned, locked dependencies that CI does not run (`engine/tests/fixtures/generate.py`).
- `supabase functions deploy` uploads the function's folder; samples, fonts and the generator in it would ship with every deploy.
- Deno 2.9.7 is the current stable release; `denoland/setup-deno` v2.0.5 (commit `22d081ff2d3a40755e97629de92e3bcbfa7cf2ed`) installs a fixed version in CI.

## Decision

- **Function.** `extract-cards` imports nothing outside the Deno runtime. It reads the user from Supabase Auth's `/auth/v1/user` and records usage through PostgREST, both with `fetch` and the service-role key, and takes `fetch`, the logger and the clock from its composition site.
- **Retry model.** `CARD_RETRY_MODEL`, optional, names the retry's model; unset, the retry uses `CARD_MODEL`.
- **Limit.** `extraction_usage` holds one row per extraction let through. The function calls `public.consume_extraction(user_id, daily_limit)`, a security-definer function executable only by `service_role`, which takes a per-user advisory lock, counts the user's rows since the start of the UTC day, and inserts one only under the limit. Clients may select their own rows and nothing else.
- **Errors.** Besides the codes the issue lists, a malformed body is 400, a method other than `POST` is 405, and an unexpected failure propagates as 500.
- **Eval.** It lives in `tools/eval/`, written in Deno against the function's own extraction module. The samples are generated by `tools/eval/generate.py`, a uv script with pinned and locked Pillow, NumPy and fontTools, run by hand like the engine's. Candidates are ID patterns resolved at run time to the newest matching model with image input and structured outputs. Spend is recorded in the committed ledger `tools/eval/spend.json`.
- **Checks.** `deno.sh` runs `deno lint` with `deno check`, `deno fmt --check`, and `deno test` for `make lint`, `make format` and `make test`, over the TypeScript under `supabase/functions/` and `tools/eval/`. It skips with the reason where deno is not installed. CI installs Deno 2.9.7 on both runners.

## Consequences

- The function has nothing to pin but the runtime, and its tests stand in for every external call with one fake `fetch`.
- The function reads the legacy `SUPABASE_SERVICE_ROLE_KEY`; disabling legacy keys on the project would break it until it reads `SUPABASE_SECRET_KEYS`.
- An extraction counts once it reaches the model, whatever the model returns, so a user cannot retry around a failed reply indefinitely.
- One user's concurrent extractions wait for each other's count; different users' do not, except on a hash collision. The lock is seeded apart from the revision trigger's, so an extraction never waits for a sync write.
- The eval measures exactly what the function deploys, and a candidate list written today still resolves when a newer model of the same family ships.
- The Deno release is stated in `README.md` and `.github/workflows/ci.yml`; no bot proposes its bump.
- The 24 sample images and the 11 MB of fonts live in the repository.

## Signs the decision was wrong

- The edge runtime lacks a web API the function uses, so a deploy fails where the tests passed.
- The function needs a call supabase-js makes simpler than `fetch`, and the hand-written calls start to grow.
- Users hit the limit through failed extractions often enough to report it.
- The eval's ranking on the synthetic set disagrees with how the chosen model does on real photos.
- A pattern in `candidates.json` resolves to a model the owner did not mean to measure.
