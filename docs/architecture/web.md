# Web

The web app in `web/`: its stack, the rules that keep it portable between Vercel and a container, its image, the session and the proxy, the shell and its pages' common parts, the server reads every feature makes, the theme and the user's choice of it, and its checks. Each feature has its own document ([ADR 0081](adr/adr/0081-document-each-web-feature-in-its-own-responsibility-document-beside-web-md-and-name-each-test-file-s-behaviour-in-one-line.md)): [`web-account.md`](web-account.md), [`web-decks.md`](web-decks.md), [`web-study.md`](web-study.md), [`web-admin.md`](web-admin.md) and [`web-legal.md`](web-legal.md).

## Current decisions

### Project

- `web/` is a Next.js 16.4.1 App Router project of its own, with strict TypeScript and the `src/` layout of stack-nextjs.md §1 ([ADR 0019](adr/0019-web-app-stack-portability-and-sign-in.md)). It runs on Node.js 24.22.0, named once in `web/.nvmrc`.
- Its packages are pinned exactly in `web/package.json` and locked in `web/package-lock.json`. Dependabot's `npm` entry for `/web` proposes their moves, except TypeScript 6.1 and later, ESLint 10 and later, and `@types/node` 25 and later:
  - typescript-eslint 8.71.2 accepts TypeScript below 6.1;
  - eslint-config-next 16.4.1 brings React, import and jsx-a11y lint plugins that accept ESLint 9 at most;
  - `@types/node` follows `web/.nvmrc`, which the PM moves with the Dockerfile's base image.
- `npm audit --package-lock-only` in `web/` reports five high findings, all from one advisory, [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), published 2026-09-18: `braces` 3.0.3 and earlier overflow the stack on deeply nested patterns. It has no patched version (`gh api /advisories/GHSA-vfj7-8cjw-p6xm` gives `first_patched_version` null), so no exact upgrade or `overrides` entry removes it; Dependabot's `npm` entry for `/web` moves it once `braces` or the plugin ships a fix. Its one path is eslint-config-next 16.4.1, `@next/eslint-plugin-next` 16.4.1, `fast-glob` 3.3.1, `micromatch` 4.0.8, `braces` 3.0.3. It is not reachable:
  - it is a lint-time dependency only: `npm ls --omit=dev braces` is empty, so it is outside the production tree, and the image's runtime stage takes only the standalone server, the static files and `public/` from the build stage;
  - the plugin calls `fast-glob` only from `no-html-link-for-pages`, through `dist/utils/get-root-dirs.js` in `@next/eslint-plugin-next` 16.4.1, and only when `settings.next.rootDir` is set. `web/eslint.config.mjs` sets no `settings`, so `braces` never parses a pattern.
- `web/src/` holds the closed list of top-level folders [`structure.md`](structure.md) names ([ADR 0039](adr/0039-name-every-top-level-folder-by-its-responsibility-compose-across-domains-in-a-home-shell-and-keep-seams-off-screens.md)): the routes in `app/`, with the legal documents in a `(legal)` route group; the features `account`, `admin`, `decks`, `study` and `legal` under `features/`; the foundations `design/` (the brand's marks, the skeleton, the theme choice and its store) and `supabase/` (the Supabase adapter); `styles/`, `testing/` and `__tests__/`; and `env.ts` and `proxy.ts`.
- Every user-facing string is Korean, in 해요체, written where it is rendered; the root layout declares `lang="ko"`.
- Icons are `lucide-react`'s, pinned exactly like every package ([ADR 0027](adr/0027-draw-both-clients-in-the-smartman-brand-and-the-v2-screens.md)).
- The admin overview's charts are `recharts`', with `react-is` pinned to `react`'s version as Recharts asks, so the two move together ([ADR 0074](adr/0074-chart-the-overview-s-photos-and-cost-by-day-plan-model-and-prompt-version-with-recharts-each-chart-an-image-named-by-a-sentence-beside-a-table.md)). Only the admin feature's client components import it.

### Portability

- No Vercel-only feature: no `@vercel/` package and no `runtime = 'edge'` anywhere under `web/`. `make lint` fails on either through `web.sh`, after checking that its pattern still finds both in two control lines.
- The build is `output: "standalone"`, and runs on the Node.js runtime.
- On Vercel the functions run in `hnd1` (Tokyo, AWS `ap-northeast-1`), the Supabase project's region, so each request a page makes to Supabase stays within one region ([ADR 0030](adr/0030-read-only-what-each-web-page-shows-and-size-the-web-from-the-app-tokens.md)). `web/vercel.json` declares it, as `regions`, and holds nothing else: a container never reads the file, and a key that changed behaviour, a rewrite or a header, would make Vercel and the container differ. Vercel reads the file from the project's Root Directory, `web`, and it overrides the region set in the project's settings. Vercel's function-region documentation (updated 2026-08-11) deploys Routing Middleware to every region whatever this setting says; `proxy.ts` makes no request to Supabase while the signing key is cached in the process and the session's access token is fresh, so where it runs adds no request to a page. A container runs where it is deployed, and its operator places it near the Supabase project.
- The configuration is environment variables, parsed once by `web/src/env.ts`: `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. A missing or malformed value, or a key that is not a publishable key, fails the build. All are public, and no secret is read: the app uses the publishable key and the user's session.
- They are frozen into the build, so a build, and an image, belongs to one Supabase project. `web.sh` builds with the values of `app/config/dev.json` unless the environment already sets them.
- `GET /api/health` answers `{"status":"ok"}` with 200 and reads nothing.
- `next.config.ts` traces the engine's `.wasm` into the `/record` route's output with `outputFileTracingIncludes`, a Next.js option and no Vercel-only feature, so the standalone server and each serverless function carry the file the server reads ([ADR 0047](adr/0047-read-the-web-record-through-two-server-functions-and-fold-it-through-the-engine-on-the-server.md)).

### Image

- `web/Dockerfile` is built from the repository root: `docker build -f web/Dockerfile .`, with both variables as `--build-arg`. `web/Dockerfile.dockerignore` admits only `web/`, `app/assets/fonts/` and `engine-wasm/pkg/` ([ADR 0022](adr/0022-study-on-the-web-with-the-engine-in-the-browser.md)).
- Three stages install the locked packages, build, and copy the standalone server, the static files and `public/` into the runtime stage. Each starts from the same index digest of `node:24.22.0-trixie-slim`, and the frontend is pinned by digest in the `# syntax=` line.
- The runtime stage runs `node server.js` on port 3000 as the base image's `node` user, uid 1000.
- Dependabot's `docker` entry for `/web` proposes only a new digest of the same `node:24.22.0-trixie-slim` tag; it ignores every Node.js release change. `make lint` fails while a `FROM` names another release than `web/.nvmrc`, and `web.sh` fails while the running Node.js differs from that file, so a release change moves `web/.nvmrc`, the `node-version` of `.github/workflows/ci.yml`'s `setup-node` step and the three `FROM` digests together, which Dependabot cannot do. The PM moves them, in one PR, to a new LTS release verified per ci.md.
- What the image runs is the web app alone; nothing in it may reach a Supabase secret.

### Session and proxy

Sign-in and the account page are the `account` feature's ([`web-account.md`](web-account.md)); this section states the session every route reads.

- The session is Supabase Auth's, in the cookies `@supabase/ssr` writes. `web/src/supabase/` holds the server client, over the request's cookies, the browser client, and `readSession`, which verifies a session with `getClaims` and returns `signed-in` with the email, `signed-out`, or `unreachable`.
- The server client waits for the request (`connection()`) before it starts: Supabase Auth's client reads the clock as it starts, which a prerender, a link's prefetch included, refuses.
- `web/src/proxy.ts` runs on every path but `/api`, `_next/static`, `_next/image`, `favicon.ico`, `brand/` and the `.svg`, `.png` and `.webmanifest` files of `public/`. It refreshes the session cookies and sends a `signed-out` visitor to `/login` from every path but `/login`, `/auth/callback`, `/terms` and `/privacy`. An `unreachable` Supabase lets the request through, so an outage signs no one out.

### Shell

- The signed-in pages, 오늘 (`/`), 덱 (`/decks`), a deck (`/decks/[id]`), 기록 (`/record`) and 계정과 설정 (`/account`), share the layout of the `(shell)` route group, `web/src/app/(shell)/layout.tsx` ([ADR 0038](adr/0038-lay-the-web-out-as-a-responsive-shell-with-a-side-menu-from-1024-px-and-a-tab-bar-below-it.md)). The admin area (`/admin`, [`web-admin.md`](web-admin.md)) sits inside it too. The sign-in, study and legal pages stand outside it.
- From 1024 px wide, a side menu 240 px wide, pinned as the page scrolls, the behaviour ADR 0038 decides: a column on the surface with its hairline border runs the page's whole height beside the content, however long the page, and the menu inside it is sticky at the top, one viewport high, so it stays in view (issue #160). The menu holds the lockup, which opens 오늘; 오늘, 덱 and 기록, each after Lucide's sun, layers or column chart, the current one on the brand tint in ink and bold, the others in `ink-2`; and at its foot the account's initial and "계정과 설정". The content sits beside it in a column up to 1040 px wide.
- Below 1024 px, a top bar with the lockup and the account's initial, named "계정과 설정", and a tab bar at the foot on the surface over a hairline, 64 px high: 오늘, 덱 and 기록, the current one in ink and bold, the others muted. The content stacks.
- Both menus are a navigation landmark named "주 메뉴", only one shown at a time, and mark the current page with `aria-current="page"`; 덱 is current on a deck's page. The content is the page's one `main`, which "본문으로 건너뛰기", the first stop of the keyboard and visible once focused, moves the focus to.
- The menus read the current page from the URL, which the static shell does not know, so each renders behind a Suspense boundary with the same menu and no page current until the URL is read.
- A page's one study button, "모두 학습" on 오늘 and "학습하기" on a deck, carries its Enter key, shown from 1024 px wide: Enter opens it from anywhere on the page but a link, button, field or other control, which keep their own Enter.
- The screens follow the principles, tokens and v3 look of [`design.md`](design.md) inside the shell, content in a 1040 px column, and the study card up to 720 px wide ([ADR 0027](adr/0027-draw-both-clients-in-the-smartman-brand-and-the-v2-screens.md), [ADR 0038](adr/0038-lay-the-web-out-as-a-responsive-shell-with-a-side-menu-from-1024-px-and-a-tab-bar-below-it.md)); each feature's document describes its pages.
- Every failure page gives a way onward, besides any retry (#209): `web/src/app/error.tsx` says "문제가 생겼어요" with "다시 시도" and "오늘로 가기", a link to `/`; `web/src/app/not-found.tsx` says "찾는 페이지가 없어요" with "덱 목록", a link to `/decks`.
- While a page waits on the server, a skeleton of its own layout holds its place ([ADR 0031](adr/0031-keep-the-web-theme-choice-in-the-browser-draw-google-sign-in-at-the-app-height-and-hold-each-page-with-a-skeleton.md)): the heading, the today card with its ring and button and the next seven days on `/`; the heading, the search and three deck rows on `/decks`; the breadcrumb, the header, the navy card with its button, the search, the row above the cards and four cards on `/decks/[id]`; the header with its progress bar, the previous card's place outlined as it is while empty, the card and the two answer buttons on `/study`; the profile card, the theme choice and the sign-out row on `/account`; the selector and the four charts' cards on `/record`. Each placeholder is the size of what replaces it, its text lines as tall as their type style's line height, so nothing moves when the content arrives. `web/src/design/skeleton.tsx` draws them: hidden from screen readers, which hear its sentence ("오늘 할 카드를 불러오는 중이에요.", "덱을 불러오는 중이에요.", "카드를 불러오는 중이에요.", "계정을 불러오는 중이에요.", "기록을 불러오는 중이에요.") in a visually hidden status inside an `aria-busy` region, and pulsing to 40% opacity and back over 1.2 s, as the phone's skeleton rows fade, only under `prefers-reduced-motion: no-preference`.

### Server reads

- The web app is online-first: it reads and writes the server tables of [`server.md`](server.md) with the user's session, under row-level security, and keeps no local database. Nothing creates or edits decks or cards on the web.
- Reads run on the server, in each page's Server Component, and read only what the page shows, with no cache ([ADR 0030](adr/0030-read-only-what-each-web-page-shows-and-size-the-web-from-the-app-tokens.md)). Each feature's document lists what its pages read.
- Each read keeps the signed-in user's own rows, since row-level security also lets every user read other users' public decks and their cards ([`server.md`](server.md)), leaves out every deck and card with `deleted_at` set and every card of such a deck, and parses each row at the boundary. It reads its tables in pages of 1000 rows, PostgREST's `max_rows` in `supabase/config.toml`: the first page with PostgREST's exact count, then every remaining page together, so it waits on two requests at most. A failure reaches the page as a value, `unreachable`, `rejected`, `failed` or `unreadable`, which it shows as one sentence in place of the list; the codes map as the phone's do ([`sync.md`](sync.md)).

### Theme

- `web/src/styles/globals.css` declares the colour tokens of `app/lib/design/theme.dart` ([`design.md`](design.md)) in `@theme`, under the same names in kebab case, the radii of `AppRadius`, the type scale of `AppType` with each style's size, line height, weight and tracking, the 560 px list and 720 px study columns, the card and raised shadows, and Google's button tokens. It overrides each colour with the dark set under `prefers-color-scheme: dark` while the user's choice is not 라이트, and under the choice 다크 whatever the system's mode.
- The user picks 시스템 (the default), 라이트 or 다크 in `/account`'s "화면", a radio group of three native radios labelled by that heading ([ADR 0031](adr/0031-keep-the-web-theme-choice-in-the-browser-draw-google-sign-in-at-the-app-height-and-hold-each-page-with-a-skeleton.md)). The choice applies at once, as `data-theme` on `<html>` (absent for 시스템), and is then kept in this browser's `localStorage` under `smartman.theme`; when the browser refuses to keep it, the page stays in it and says so. The root layout's `<head>` runs an inline script first, before the body is parsed, that sets `data-theme` from the stored choice, so every page's first paint is drawn in it; storage that cannot be read leaves the system's. Tailwind's `dark:` variant follows the same rules as the colours. `web/src/design/theme.ts` holds the key, the script and the store.
- Spacing and sizes come from the same file ([ADR 0030](adr/0030-read-only-what-each-web-page-shows-and-size-the-web-from-the-app-tokens.md)): Tailwind's spacing unit is pinned at 4 px, so each step of `AppSpace` is a whole number of it; `AppSpace`'s gutter, row gap and section gap are the tokens `gutter`, `row-gap` and `section-gap`; and each `AppSize` value a web screen draws is a token under its name in kebab case (`button`, `cta`, `tap-target`, `deck-tile` …). The markup uses these tokens, not the steps they equal.
- `web/src/styles/__tests__/theme-tokens.test.ts` fails when a colour token differs from theme.dart's, in the light set or in either rule's dark set, a Google button token from `GoogleButtonStyle`'s colours, label, mark size or Android and web spacing, a radius from `AppRadius`, a type style from `AppType` in size, line height, weight or tracking, a size token from the `AppSize` value of its name, a named gap from `AppSpace`'s, or a step of `AppSpace` from a whole number of the spacing unit.
- `web/src/styles/fonts` links to `app/assets/fonts/`. `next.config.ts` names that directory in `turbopackAdditionalRoots`, and the root layout bundles Pretendard's Regular, Medium, SemiBold, Bold and ExtraBold with `next/font/local`; nothing is downloaded at run time.
- `web/public/` holds `favicon.svg`, which follows the colour scheme, `favicon-32.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` and `manifest.webmanifest` with theme colour `#1F2A44`; the root layout names them, `brand/` holds the marks, and `google/` Google's "G" mark.
- Buttons are at least 52 px high (`min-h-button`), the primary 56 (`min-h-cta`), and the focus ring is a visible outline.
- Every text colour the login, account or empty home page, the shell's menus, the today card or the forecast draws meets WCAG AA, 4.5:1, on its ground in either theme; on the study screen, the text on a grade's fill, on a grade's chip and on an answer button meets 4.5:1, and a grade's chip on its card or the ground, and the streak's flame on the surface, 3:1.

### Checks

- `web.sh`, at the repository root, implements the `web/` part of `make lint`, `format`, `test` and `build`. Where `node` is missing it prints that it skipped; where the host's Node.js differs from `web/.nvmrc` it fails. It installs the locked packages when they are missing or older than the lock file. It builds the image quietly, and on a failure prints the build's whole log, so the failing step's own error, such as `next build`'s, reaches the output and CI's log (#229).
- `make lint`: ESLint with typescript-eslint's type-checked strict rules, `tsc --noEmit`, the portability check and the Node.js release check.
- `make format`: Prettier, over the files git tracks or would track.
- `make test`: the Vitest suite (`web/src/**/__tests__/`), then, where Docker and buildx answer, the image built and run, its health and non-root uid asserted, and the Playwright specs in `web/e2e/` run against it; `web/e2e/study.spec.ts` skips there. Then `supabase/test-web.sh` runs that spec against a throwaway local stack (§Tests).
- `make build`: `next build`, then the image where Docker and buildx answer.
- CI runs `web.sh` in its ubuntu job, on the Node.js that `.github/workflows/ci.yml` installs for the WebAssembly tests; `web.sh` fails there when it differs from `web/.nvmrc`. The ubuntu runner has Docker, so that job runs the image and the e2e specs, `supabase/test-web.sh`'s included; the macOS job runs only the iOS simulator build.
- `next build` refuses a `"use client"` module whose value imports reach a `server-only` module, and neither `tsc` nor Vitest checks that, so a test walks the imports (stack-nextjs §13).

- A step in either spec that clicks or presses a key on a page just loaded goes through `untilReacted` (`web/e2e/until-reacted.ts`): it acts only while the page shows no reaction and ends once it does, since an action before the page hydrates finds no handler and the server-rendered markup is there before then (#152).
