# Web decks

The web's `decks` feature: the deck list, a deck's page, the first run with no deck, the card content blocks and how a side is drawn. The pages' shell and the server reads they share are [`web.md`](web.md)'s; the app's `deck` domain is [`deck.md`](deck.md).

## Current decisions

### Reads

- `/decks` (덱) reads what `/` (오늘) reads, `decks`' `readDeckList` and `study`'s `readToday` and `readRecentRetention` together ([`web-study.md`](web-study.md)), without the streak; `/decks/[id]` reads `readLibrary` over the deck it names (that deck and its cards with both sides) and `readToday`, together; its title reads the same `readLibrary` through React's `cache` (`read-deck.ts` beside the page), so the page and its title make one request (#281).

### Authoring

- Creation lives inside `decks` ([ADR 0122](adr/0122-create-decks-and-reviewed-cards-on-the-web.md)). First-run home and the deck list offer "새 덱 만들기"; every deck offers "카드 추가". Their sheet offers "직접 입력", "사진 찍기", "앨범에서 고르기" and "파일에서 고르기" as grouped text rows.
- Manual deck creation asks for its name and opens it. Manual card entry draws one front group and one back group, supports text and meanings with typed labels and examples, and offers "저장" and "저장하고 다음 카드". It inserts new cards only; the existing-card rows still reveal their backs. Closing an edited draft asks before discarding it; a pristine or saved exit closes directly. A failed write retains the draft; a duplicate warns and offers "그래도 추가", never replacing an existing card.
- Each Server Action verifies the session and scopes reads and writes to that owner and a live deck. Stable client ids make retries ignore an existing row rather than overwrite it. New cards carry `free` version 1, versioned blocks and the phone's normalized card key; the database assigns revisions. Stored cards are not rewritten.
- Photo import follows the phone's states and words ([`ai-extraction.md`](ai-extraction.md) §The app, #506) inside the authoring sheet. "사진 찍기" and "앨범에서 고르기" open the browser's picker from the row itself, any image, up to 50; a cancelled picker opens nothing. The chosen photos start reading at once: the allowance is read first, and with fewer left than chosen only the first are kept, with "오늘 n장 더 만들 수 있어요. 처음 n장만 읽어요." (or "이번 달 …"), and with none, the limit's failure before any photo is sent; where the allowance cannot be read every photo is sent. One photo shows "카드를 찾고 있어요" with its thumbnail, a bar, skeleton rows, the privacy note and "취소", or its failure with "다시 시도" where sending it again can help and "다른 사진 고르기" (or "다시 찍기") where a new photo can. Several show "사진 n장 중 k장 읽음", or "사진 n장을 읽지 못했어요" once only failures remain, over a bar of the k read, and a row per photo with its thumbnail, "사진 i" and its state in words and an icon (기다리는 중, 읽는 중, 카드 n장 with a check in ink, or the failure's message), a failed one with "다시 시도" where retryable and "빼기", and, while any failed photo is retryable, "실패한 사진 다시 시도" beside "취소" re-sends all of them at once (the owner, 2026-11-01); once every photo is read the list opens. "취소" while photos are added to a list returns to it; otherwise it closes, asking first once cards are read.
- Every photo is prepared in the browser as the phone's `downscalePhoto` prepares it (`extract-photo.ts`): decoded upright by its EXIF orientation, scaled to at most 2048 px on its long side and JPEG-encoded under the 3 MiB upload bound, trying qualities 85, 70, 55 and 40; the source's size is not limited. A file the browser cannot decode, HEIC on a browser without HEIC support among them, fails as `unreadable`, "이 사진을 읽을 수 없어요. JPEG, PNG, WebP 사진을 골라 주세요.", and one too large at the lowest quality as `refused`. A retry sends the prepared photo again without preparing it twice. The action request limit is 4 MiB, including its envelope. Photos are read one at a time, as the browser runs one Server Action at a time. Camera capture is a browser hint, and some browsers open a file picker instead.
- Each photo's failure is one of the phone's kinds with its `app_ko.arb` message (`photo-failure.ts`): the function's 401 `signIn`, 403 `suspended` `suspended`, 413 and 415 `refused`, 422 `noCards`, 429 with its limit `limit`, 502 `model`, and any other status or an unreadable success `service`; an action call that never returns `offline`. `model`, `service` and `offline` offer "다시 시도", as the phone's `isRetryable`. `readPhoto` sends a photo once more when its request got no response, not a timeout: the function counts a photo before its model call, so the resend counts again only where the first request reached the function before the connection failed. An answered request is never resent automatically. A request waits 145 s for the function: past the function's worst case, a retry started by 75 s that times out at 60 s, about 135 s ([ADR 0130](adr/0130-retry-a-failed-photo-once-within-one-usage-and-record-each-extraction-s-outcome.md)), and under the Edge Function's 150 s wall clock; a request still unanswered then is logged as `timeout`, fails as `service`, and is not resent. It logs one line per photo, `read_photo`, with the function's last status (or `timeout`, `unreachable`), the latency in ms, the attempts, the upload's size, the outcome's kind and the card count, never the image or the token.
- A successful response opens the phone's review list (`import-list.tsx`, the phone's `ImportListView`), under "카드 n장을 만들었어요", or "단어를 찾았어요" when every card is vocabulary. Under the title, the deck line: "덱 'name'에 추가돼요", or "새 덱에 추가돼요", the name a button that opens "추가할 덱", every deck the page read (a deck's page reads its own deck alone) and "새 덱", the chosen one checked. The cards are in sections, a section the cards of one topic of one photo, of one kind, identify cards apart (`section-form.ts`, the phone's `ImportSection`), each photo's in the order each first appears; with one photo the sections are listed, and with several each photo's are a group headed by its thumbnail, "사진 i" and "카드 n장" with a chevron, a button that collapses or expands the group, which starts expanded; a collapsed group's selected cards are still saved. A section is headed by its topic and count, "판별 · topic" for identify cards, whose cards start left out, as the phone's `isIncluded`, and by its form menu, a button naming the form ("앞면에 단어", "앞면에 뜻", "양쪽 방향", "앞면에 질문" or "앞면에 답"), read as "topic 카드 모양, form", opening a pull-down menu on `raised` with the `group` radius and the raised shadow: for vocabulary "앞면에 단어", "앞면에 뜻" and "양쪽 방향 모두", then "첫 뜻만", "라벨 표시", "발음 표시" while a row has a pronunciation and "유의어 등 표시" while one has an extra; for notes "앞면과 뒷면 바꾸기" while a row is not a table or cloze card; then, after a heavier hairline, "이 묶음 빼기" while any card is included, else "이 묶음 넣기". A choice closes the menu; Escape closes it alone and returns focus to its button. Each row shows its first card in its section's form; "양쪽 방향" saves an entry as two cards, the reversed one under an id of its own, and a table or cloze card is saved whole in any form, as the phone's `ImportRow.cards`. Each deck's section forms are remembered in the browser, under `smartman.photoImportForms` in the phone's JSON, when cards are saved into it, and taken when that deck is chosen. "사진 더 추가" adds photos to the list, and "카드 n장 추가", n the cards the forms make, saves, a new deck first named in the phone's "새 덱" sheet with "만들기". The list's round checks select cards; plain notes and vocabulary open an edit sheet on the entry as read, word to meaning, retaining structured meanings, labels and examples. Cloze and table cards are non-interactive review previews; their selection check remains available, and they retain their blocks and filled-text backs. Only the explicit add action inserts selected cards into the chosen deck or a named new deck. The phone's merge of one key's candidates into one row, its "이미 덱에 있어요" and its swipe to leave a row out are not drawn: each candidate is its own row, and a duplicate is refused on saving. Discarding candidates saves no card; an import with candidates asks before discard. Closing the browser loses the unsaved job; it is not the phone's persistent background job.
- Spreadsheet import ([ADR 0125](adr/0125-add-cards-from-an-xlsx-or-csv-file-by-choosing-columns-and-reviewing-before-save.md)) reads an `.xlsx` or a UTF-8 `.csv` in the browser, never uploading it: a file over 5 MB is refused before it is read, a sheet of more than 1,000 rows holding text before any row becomes a card. `spreadsheet.ts` reads the visible sheets' cells as the sheet shows them, through `fflate` and `ssf`; `spreadsheet-cards.ts` maps the chosen front, back and optional label and example columns to cards, under the header switch, which starts on only for a first row holding a common column name or text over a column of values, skipping rows with an empty front or back and naming rows with a cell over 500 characters. The review lists every card with its row, selected by default, and saves only "n장 추가", in requests of at most 100 through `saveCards`, which names the repeating card's index so a duplicate is named by its row, with "n행 빼기" and "그래도 추가".
- Authoring sheets isolate keyboard focus, close on Escape and return focus. They scroll inside the viewport, keep actions reachable and use the app's colour, type, group and button tokens in both themes.

### Card content

- `web/src/features/decks/card-content.ts` reads each block's version as the phone does: none as v1, an older one upgraded through `blockUpcasters`, and a known type above its version, or an unknown type, as a placeholder, the stored card never written ([ADR 0106](adr/0106-store-each-card-s-template-and-each-block-s-version-and-id-derive-one-face-or-front-back-from-blanks-and-keep-unknown-shapes-unchanged.md)). It reads, refuses, fills and speaks a card's `cloze`, `table` and `senses` blocks as the phone's `app/lib/deck/` does, a v1 table upgraded to v2 with no span and a v2 table's spans read as the phone reads them ([ADR 0110](adr/0110-blank-a-span-of-a-table-cell-s-text-stored-at-table-block-v2-beside-whole-cell-blanks.md)), on `app/test/deck/content_test.dart`'s cases and the phone's `spokenContent`, the back the server's senses migration writes among them, as `supabase/tests/senses_migration_test.sql` asserts its stored text. `WholeCard` (`web/src/features/decks/components/whole-card.tsx`) draws a whole card, a table's span empty inside its cell's text and filled in place once revealed, and `SideText` a side with a senses block's labels ([`web-study.md`](web-study.md) for the study page's use).
- An `image` block is read as the phone reads it, its boxes in fractions of the image's own size, and refused on the same cases; a photo with a box makes a whole card, and it reads as "사진" and each box as "빈칸", or its answer once revealed ([ADR 0109](adr/0109-store-an-image-block-s-boxes-in-fractions-of-the-image-and-draw-them-with-the-image-s-one-transform.md)). `WholeCard` draws it with the phone's one transform: a container the full width, at most `60dvh` tall through a `max-width` of `60dvh` times the image's width over its height, centred, with the image's aspect ratio as its CSS `aspect-ratio`, so a tall photo fits as the phone's frame does, and each box positioned in percentages of it, filled in `hero` while hidden and outlined in 2 px of `brand`, its answer in `caption` on `brand-tint`, once revealed. The web reads no photo from the bucket yet, so the container is drawn on `ground`, with the boxes, until the follow-up that reads it.
- An `audio` block is read as the phone reads it, `{media, duration_ms}`, and refused on the same cases; it makes no whole card, and reads as "소리", `design.md` §Copy's term ([ADR 0112](adr/0112-store-an-audio-block-by-media-id-and-length-up-to-60-seconds-and-play-the-front-s-sound-once-as-a-study-card-appears.md)). `audioOf` gives a side's sounds and `audioLength` a sound's length as `0:07`, rounded up to the second, for the study page, which plays them ([`web-study.md`](web-study.md)). `WholeCard` draws a sound as "소리" and its length, hidden from a screen reader, which reads its label, and holds no control, since the deck page's card is a button.
- A deck's tile is the app's ([ADR 0103](adr/0103-give-each-deck-an-icon-and-a-colour-stored-as-two-unchecked-keys-and-drawn-on-its-tile-in-place-of-the-initial.md)): `readLibrary` and `readDeckList` read `decks.icon` and `decks.color`, and the tile draws the icon in ink, the Lucide icon the app draws for each key, on the key's `--color-deck-*` token. A null key, or one this version does not know, draws `layers` on the colour the deck's id selects: the sum of its UTF-16 code units modulo the palette's six, in the app's order (`deck-tint.ts`). The initial letter is gone. A newly created deck keeps the default appearance.
