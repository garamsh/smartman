# Web decks

The web's `decks` feature: the deck list, a deck's page, the first run with no deck, the card content blocks and how a side is drawn. The pages' shell and the server reads they share are [`web.md`](web.md)'s; the app's `deck` domain is [`deck.md`](deck.md).

## Current decisions

### Reads

- `/decks` (덱) reads what `/` (오늘) reads, `decks`' `readDeckList` and `study`'s `readToday` and `readRecentRetention` together ([`web-study.md`](web-study.md)), without the streak; `/decks/[id]` reads `readLibrary` over the deck it names (that deck and its cards with both sides) and `readToday`, together; its title reads the same `readLibrary` through React's `cache` (`read-deck.ts` beside the page), so the page and its title make one request (#281).

### Authoring

- Creation lives inside `decks` ([ADR 0122](adr/0122-create-decks-and-reviewed-cards-on-the-web.md)). First-run home and the deck list offer "새 덱 만들기"; every deck offers "카드 추가". Their sheet offers "직접 입력", "사진 찍기", "앨범에서 고르기" and "파일에서 고르기" as grouped text rows.
- Manual deck creation asks for its name and opens it. Manual card entry draws one front group and one back group, supports text and meanings with typed labels and examples, and offers "저장" and "저장하고 다음 카드". It inserts new cards only; the existing-card rows still reveal their backs. Closing an edited draft asks before discarding it; a pristine or saved exit closes directly. A failed write retains the draft; a duplicate warns and offers "그래도 추가", never replacing an existing card.
- Each Server Action verifies the session and scopes reads and writes to that owner and a live deck. Stable client ids make retries ignore an existing row rather than overwrite it. New cards carry `free` version 1, versioned blocks and the phone's normalized card key; the database assigns revisions. Stored cards are not rewritten.
- Photo import reads `extraction_allowance` before enabling reading. It accepts up to 50 JPEG, PNG or WebP files, at most 6 MiB each, read sequentially through an authenticated Server Action to the existing signed-in function. Uploads are bounded to 3 MiB; larger accepted source files are resized to at most 2048 px and JPEG-encoded in the browser. The action request limit is 4 MiB, including its envelope. Stopping prevents subsequent photos; an in-flight request can still consume allowance. Each photo has its progress and an actionable failure; picker cancellation keeps the source available. Camera capture is a browser hint, and some browsers open a file picker instead.
- A successful response remains candidates grouped by photo and topic. The list's round checks select cards; plain notes and vocabulary open an edit sheet, retaining structured meanings, labels and examples. Cloze and table cards are non-interactive review previews; their selection check remains available, and they retain their blocks and filled-text backs. Only the explicit add action inserts selected cards into the current deck, a chosen existing deck, or a named new deck. Discarding candidates saves no card; an import with candidates asks before discard. Closing the browser loses the unsaved job; it is not the phone's persistent background job.
- Spreadsheet import ([ADR 0125](adr/0125-add-cards-from-an-xlsx-or-csv-file-by-choosing-columns-and-reviewing-before-save.md)) reads an `.xlsx` or a UTF-8 `.csv` in the browser, never uploading it: a file over 5 MB is refused before it is read, a sheet of more than 1,000 rows holding text before any row becomes a card. `spreadsheet.ts` reads the visible sheets' cells as the sheet shows them, through `fflate` and `ssf`; `spreadsheet-cards.ts` maps the chosen front, back and optional label and example columns to cards, under the header switch's default, skipping rows with an empty front or back and naming rows with a cell over 500 characters. The review lists every card with its row, selected by default, and saves only "n장 추가", in requests of at most 100 through `saveCards`, which names the repeating card's index so a duplicate is named by its row, with "n행 빼기" and "그래도 추가".
- Authoring sheets isolate keyboard focus, close on Escape and return focus. They scroll inside the viewport, keep actions reachable and use the app's colour, type, group and button tokens in both themes.

### Card content

- `web/src/features/decks/card-content.ts` reads each block's version as the phone does: none as v1, an older one upgraded through `blockUpcasters`, and a known type above its version, or an unknown type, as a placeholder, the stored card never written ([ADR 0106](adr/0106-store-each-card-s-template-and-each-block-s-version-and-id-derive-one-face-or-front-back-from-blanks-and-keep-unknown-shapes-unchanged.md)). It reads, refuses, fills and speaks a card's `cloze`, `table` and `senses` blocks as the phone's `app/lib/deck/` does, a v1 table upgraded to v2 with no span and a v2 table's spans read as the phone reads them ([ADR 0110](adr/0110-blank-a-span-of-a-table-cell-s-text-stored-at-table-block-v2-beside-whole-cell-blanks.md)), on `app/test/deck/content_test.dart`'s cases and the phone's `spokenContent`, the back the server's senses migration writes among them, as `supabase/tests/senses_migration_test.sql` asserts its stored text. `WholeCard` (`web/src/features/decks/components/whole-card.tsx`) draws a whole card, a table's span empty inside its cell's text and filled in place once revealed, and `SideText` a side with a senses block's labels ([`web-study.md`](web-study.md) for the study page's use).
- An `image` block is read as the phone reads it, its boxes in fractions of the image's own size, and refused on the same cases; a photo with a box makes a whole card, and it reads as "사진" and each box as "빈칸", or its answer once revealed ([ADR 0109](adr/0109-store-an-image-block-s-boxes-in-fractions-of-the-image-and-draw-them-with-the-image-s-one-transform.md)). `WholeCard` draws it with the phone's one transform: a container the full width, at most `60dvh` tall through a `max-width` of `60dvh` times the image's width over its height, centred, with the image's aspect ratio as its CSS `aspect-ratio`, so a tall photo fits as the phone's frame does, and each box positioned in percentages of it, filled in `hero` while hidden and outlined in 2 px of `brand`, its answer in `caption` on `brand-tint`, once revealed. The web reads no photo from the bucket yet, so the container is drawn on `ground`, with the boxes, until the follow-up that reads it.
- An `audio` block is read as the phone reads it, `{media, duration_ms}`, and refused on the same cases; it makes no whole card, and reads as "소리", `design.md` §Copy's term ([ADR 0112](adr/0112-store-an-audio-block-by-media-id-and-length-up-to-60-seconds-and-play-the-front-s-sound-once-as-a-study-card-appears.md)). `audioOf` gives a side's sounds and `audioLength` a sound's length as `0:07`, rounded up to the second, for the study page, which plays them ([`web-study.md`](web-study.md)). `WholeCard` draws a sound as "소리" and its length, hidden from a screen reader, which reads its label, and holds no control, since the deck page's card is a button.
- A deck's tile is the app's ([ADR 0103](adr/0103-give-each-deck-an-icon-and-a-colour-stored-as-two-unchecked-keys-and-drawn-on-its-tile-in-place-of-the-initial.md)): `readLibrary` and `readDeckList` read `decks.icon` and `decks.color`, and the tile draws the icon in ink, the Lucide icon the app draws for each key, on the key's `--color-deck-*` token. A null key, or one this version does not know, draws `layers` on the colour the deck's id selects: the sum of its UTF-16 code units modulo the palette's six, in the app's order (`deck-tint.ts`). The initial letter is gone. A newly created deck keeps the default appearance.
